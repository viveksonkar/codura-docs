# Spec — HTTP API

**Status:** Draft v0.1 · **Last updated:** 2026-11-18 · **Frozen by:** M1-08 (§3 public v1) · **ADR:** 0012

The OpenAPI document generated by FastAPI is normative once it exists; this spec is what the
Channels and Admin Console build against before then.

## 1. Conventions

### 1.1 Bases
- Admin API: `/api/admin/*` — session cookie (Admin Console) or `Authorization: Bearer sk_…`.
- Platform API: `/api/platform/*` — session of a User with `is_platform_admin` only.
- Public API: `/api/v1/*` — `Authorization: Bearer pk_…` (Channel Key) only.
- Every admin route resolves a `TenantContext` from the session's current Tenant (or the `sk_`
  key's Tenant) before touching data. Tenant IDs in paths or bodies are never trusted.
- Health: `/healthz`, `/readyz` (no auth).

### 1.2 Format
JSON, `snake_case`, UTC ISO-8601 timestamps, prefixed IDs. Lists: `?limit=` (≤ 100, default 20)
and `?cursor=`; response `{ "items": [...], "next_cursor": "…" | null }`.

### 1.3 Errors
```json
{ "error": { "code": "document_too_large", "message": "File exceeds 50 MB", "request_id": "req_…", "details": {} } }
```
Codes: `unauthenticated` 401, `forbidden` 403, `origin_not_allowed` 403, `not_found` 404,
`conflict` 409 (`duplicate_document`), `validation_error` 422, `document_too_large` 413,
`unsupported_media_type` 415, `rate_limited` 429 (+ `Retry-After`), `provider_unavailable` 503,
`internal` 500.

## 3. Public Chat API v1 (frozen at M1-08)

### 3.1 Auth, Tenant resolution & headers
- `Authorization: Bearer pk_…` (required). `sk_…` → 401. **The key alone determines the
  Tenant and Assistant.** No request field, header or path segment can select a Tenant, and IDs
  from another Tenant (e.g. a `conversation_id`) return 404, never 403, so they can't be probed.
- Revoked keys and keys of suspended Tenants → 401.
- `Origin` must be in Allowed Origins for `widget`/`wordpress` keys (SEC-05).
- `X-Codura-Visitor: <uuid>` (required; client-generated, persisted).
- `X-Codura-Client: hosted/1.0.0` | `widget/1.2.0` | `wordpress/1.0.0` | `android/1.0.0` (informational).
- `Accept-Language` selects welcome text and UI strings. It does **not** decide the answer
  language, which follows the question (rag-pipeline.md §3).

### 3.2 `GET /api/v1/channel/config`
```json
{ "assistant": { "id": "asst_…", "name": "Acme Help", "welcome_text": "नमस्ते! पूछिए…", "default_language": "en" },
  "theme": { "accent": "#2563eb", "position": "right", "title": "Ask us", "logo_url": null },
  "ui_languages": ["en", "hi", "ar"],
  "features": { "feedback": true, "citations": true },
  "limits": { "max_question_chars": 2000 } }
```

### 3.2a `GET /api/v1/hosted/{tenant_slug}/{assistant_slug}` (no auth)
Returns `{ "channel_key": "pk_…", "api": "https://…" }` for the Hosted Chat Page if the Assistant
has `hosted_enabled`. Otherwise it returns 404 with the same body and timing as an unknown slug
(no enumeration). Rate-limited per IP.

### 3.3 `POST /api/v1/chat/stream`
Request:
```json
{ "question": "How do I reset the X200?", "conversation_id": "conv_…",     // conversation_id optional
  "visitor_email": "a@b.com", "consent": true }                            // optional; first message only (ADR-0023)
```
`required` email setting without an email → 422 `visitor_email_required`. Quota exhausted → normal
stream with `done.finish_reason: "limit"` and the Assistant's limit-reached text (no LLM call).
`channel/config` exposes `visitor_email: {mode, consent_text, privacy_url}` and `branding: bool`.
Response: `200 text/event-stream`. Each event is `event: <type>\ndata: <json>\n\n`:

| Event | Data | When |
|---|---|---|
| `meta` | `{ "conversation_id", "message_id", "user_message_id", "language" }` | First, always (`language` = detected Answer Language, BCP-47) |
| `delta` | `{ "text": "…" }` | Zero or more, in order |
| `citations` | `{ "items": [{ "n": 1, "document_id", "title", "page", "heading_path": [], "snippet" }] }` | Once, after the last `delta` (empty `items` on fallback) |
| `done` | `{ "finish_reason": "stop"\|"length"\|"fallback"\|"limit"\|"cancelled", "latency_ms" }` | Last on success (token usage is internal, not exposed to Channels) |
| `error` | `{ "code", "message" }` | Last on failure after the stream opened |

Rules: clients **ignore unknown event types**; a client disconnect cancels generation
(`finish_reason: "cancelled"` is persisted); a keep-alive comment `: ping` is sent every 15 s;
pre-stream failures (auth, validation, rate limit) are normal JSON errors (§1.3), not SSE.

Shared fixtures: `docs/specs/fixtures/sse/*.txt` (created in M1-08) — both the TS and Kotlin
clients test against them.

### 3.4 `GET /api/v1/conversations/{conv_id}/messages`
Restores history for the same Channel Key's Tenant and the same Visitor ID (404 otherwise). Returns Messages with Citations.

### 3.5 `POST /api/v1/messages/{msg_id}/feedback`
`{ "value": 1 | -1, "note": "optional ≤ 500 chars" }` → `204`. Same Visitor only.
