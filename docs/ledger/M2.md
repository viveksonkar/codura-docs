# Ledger — M2: Web Channel (MVP)

**Status:** Draft v0.2 · **Last updated:** 2026-11-18 · **Milestone ref:** [roadmap.md](../roadmap.md) M2 · **ADR:** 0010, 0012, 0017

**Exit criteria:** MVP acceptance complete ([requirements.md](../requirements.md) §6, steps
1–9), including optional Visitor email capture and the unanswered-questions insight. As a Visitor, Tenant A's Hosted Chat Page and a static page with A's Widget give streamed,
cited answers in at least two languages. A's key is rejected from a non-allowed Origin. Tenant B's
key and Visitors can't reach anything of A's. The web Channel parity checklist
([channels.md](../channels.md) §6) passes.

Decomposed early on purpose: the owner wants the web interface as soon as M1 exits. The Tasks build
only on the frozen public API (specs/api.md §3, M1-08). Re-check them against what M1 delivered
before claiming.

```
Wave 0:  M2-00  M2-02  M2-04
Wave 1:  M2-01  M2-03  M2-05  M2-06
Wave 2:  M2-07  M2-08  M2-10  M2-11
Wave 3:  M2-09
```

## Wave 0

### M2-00 — Channel Keys service & admin API
- **Wave:** 0
- **Depends on:** M1 exit
- **Owns:** `services/channel_keys.py`, `api/routers/admin/channel_keys.py`, `api/auth/public.py`
- **Implements:** FR-34; SEC-04, SEC-15; ADR-0012
- **Spec:** specs/api.md §2 (channel-keys), §3.1; specs/db.md §2 (`api_keys`, `resolve_api_key`)
- **Acceptance criteria:**
  - Create (`pk_` for hosted/widget/wordpress/android/api, bound to one Assistant of the current
    Tenant), list, revoke; secret shown once; stored hashed; `last_used_at` updated asynchronously
  - Enabling `hosted_enabled` on an Assistant auto-creates its `hosted` key; disabling revokes it
  - `require_channel_key()` dependency yields `(TenantContext, Assistant, ChannelKey)` and replaces
    the M1-08 dev key
- **Status:** [ ] Not started
